### [Cache-to-Cache: KV-Cache 직접 교환으로 LLM 간 통신하는 C2C 기법](https://news.hada.io/topic?id=33983) ⭐️ 7.0/10

Cache-to-Cache\(C2C\)는 여러 LLM이 중간 텍스트 생성 없이 KV-Cache를 직접 교환해 의미 정보를 전달하는 새로운 다중 LLM 통신 방식이다. 기존 텍스트 기반 통신\(T2T\)은 고차원 내부 표현을 문자열로 압축하는 과정에서 정보 병목, 자연어의 모호성, 토큰 단위 순차 생성으로 인한 지연이라는 세 가지 제약을 겪는다. C2C는 신경망 기반 캐시 융합기가 원본 모델의 KV-Cache를 대상 모델의 표현 공간에 투영·병합하고, 학습 가능한 게이팅으로 통신 효과가 있는 계층을 선택하는 구조를 사용한다. 실험 결과 C2C는 개별 모델 대비 평균 정확도가 6.4~14.2% 높았고 T2T 대비로도 약 3.1~5.4% 개선되었으며, 지연 시간은 T2T 대비 평균 2.5배 향상되었다. 관련 코드는 C2C GitHub 저장소에 공개되어 있다.

rss · GeekNews · 9월 20일 05:52

**「배경」** 다중 LLM 시스템은 코딩, 수학, 시각 이해 등 서로 다른 영역에 특화된 모델들을 결합해 단일 모델로는 얻기 어려운 성능을 추구하며, 협업형\(능동적 메시지 교환\) 방식과 라우팅 기반\(문맥 상속\) 방식으로 나뉜다. 현재 대부분의 협업은 자연어 텍스트로 이루어지는데, 이는 모델 내부의 고차원 표현을 선형 문자열로 반복 압축해야 하므로 정보 손실과 지연이 불가피하다. KV-Cache는 모델이 입력을 처리하며 생성하는 내부 표현으로, 텍스트보다 훨씬 풍부한 의미 정보를 담고 있어 이를 직접 교환하려는 시도가 C2C의 출발점이다.

**「의의」** C2C가 실용화되면 코드 생성-문서 작성처럼 역할이 분리된 다중 에이전트 파이프라인에서 텍스트 프로토콜의 모호성 문제 없이 구조적 의미까지 정확히 전달할 수 있어, 다중 LLM 시스템의 정확도와 응답 속도를 동시에 개선할 잠재력이 있다. 다만 이 방식은 원본·대상 모델 간 캐시 융합기를 학습시켜야 하므로, 임의의 모델 조합에 즉시 적용하기보다는 사전 학습된 모델 쌍이나 패밀리 내에서 우선 활용될 가능성이 크다.

### [Claude가 조율한 GPU 클러스터로 RSA-896 인수분해 성공](https://saweis.net/posts/rsa-896.html) ⭐️ 6.0/10

Anthropic의 Claude가 기존 수체 체\(number field sieve\) 구현체인 CADO-NFS를 GPU에서 구동하도록 포팅하고, 유휴 GPU 자원을 스캐빈징하는 방식으로 최대 2048개 GPU 클러스터를 직접 조율해 10일간 총 약 30 GPU-year 규모의 연산을 수행함으로써 896비트 RSA 정수를 인수분해했다. 이는 새로운 암호 해독 알고리즘이 아니라 수십 년간 발전해온 수체 체와 CADO-NFS를 대규모 분산 GPU 인프라에서 안정적으로 운영한 엔지니어링 성과에 해당한다. 이번 결과는 현재도 사용되는 768비트 RSA 키\(예: Instagram이 게시하는 DKIM 키\)가 대규모 GPU 자원을 동원하면 실질적으로 인수분해 가능한 위협 범위 안에 들어와 있음을 시사한다.

hackernews · madars · 9월 20일 02:19 · [커뮤니티 반응](https://news.ycombinator.com/item?id=49771966)

**「배경」** RSA 암호화는 큰 합성수를 두 소수로 인수분해하기 어렵다는 사실에 안전성을 두며, RSA-896은 296자리\(약 896비트\)의 인수분해 난제로 RSA Factoring Challenge에서 제시된 숫자 중 하나이다. 이러한 큰 정수를 인수분해하는 표준적인 고전 알고리즘은 1990년대 개발된 일반 수체 체\(General Number Field Sieve, GNFS\)이며, CADO-NFS는 이를 구현한 오픈소스 소프트웨어로 여러 컴퓨터에 계산을 분산하는 기능을 이미 지원해왔다. RSA-896보다 작은 768비트 키는 2009년경 이미 학계에서 인수분해된 바 있어, DKIM 서명 등에 여전히 사용되는 768비트 RSA 키의 보안성은 오래전부터 우려의 대상이었다.

**「영향」** Instagram DKIM 키처럼 여전히 768비트 RSA를 사용하는 서비스들은 이제 유휴 GPU 클러스터만으로도 실용적인 인수분해 위협에 노출됨을 보여주며, 이는 해당 키 길이를 사용하는 시스템의 조기 폐기 필요성을 부각시킨다. 다만 커뮤니티에서는 이번 성과가 새로운 암호 해독 알고리즘이 아니라 기존 수체 체를 GPU 클러스터에 조율한 공학적 성취일 뿐이라는 점에서, 2048비트 이상의 현대 RSA 키에 대한 실질적 위협으로 확대 해석하는 것은 경계해야 한다는 지적이 있다.

**「커뮤니티 반응」** 일부 댓글은 Instagram이 여전히 768비트 RSA DKIM 키를 공개하고 있다는 점을 지적하며 이제 이를 인수분해하는 것이 '주말 GPU 프로젝트' 수준일 수 있다고 우려했다. 다른 참여자들은 이미 확립된 알고리즘을 쓴 것뿐이라며 참신성이 낮다고 지적했지만, 어차피 예약된 클러스터의 유휴 용량을 활용한 것이므로 사실상 비용이 들지 않는 재미있는 실험이라는 반론도 있었고, 관련해 부분 해시 충돌 실험 등 유사한 유휴 GPU 활용 아이디어도 공유되었다.

### [Firefox AI 통합에 맞서 시작된 base browser 하드포크 프로젝트](https://news.hada.io/topic?id=33993) ⭐️ 6.0/10

Mozilla가 Firefox에 AI 기능을 지속적으로 통합하자, 여러 Firefox 포크 프로젝트들이 Mozilla와 독립된 공통 기반을 함께 유지하자는 취지에서 base browser 프로젝트를 시작했다. base browser는 Firefox 153 ESR을 기반으로, Tor Browser나 Waterfox처럼 문제 기능을 비활성화하는 소프트 포크 방식과 달리 사용자에게 적대적인 기능을 코드베이스에서 완전히 삭제하는 것을 원칙으로 삼는다. AI 통합 코드를 제거하는 패치만 해도 1,605개 파일, 852,297줄 삭제, 37MB 규모에 달했으며, 이후 소규모 자원봉사 팀이 패치 크기를 1MB 미만으로 줄이는 스크립트와 Git irreversible-delete 플래그, 커스텀 Python 코드를 이용해 재패치가 가능하도록 정비했다. 프로젝트 시작자는 자금과 개발 역량 부족으로 장기 유지가 어려울 수 있음을 인정하면서도, Firefox 소스 빌드 방법을 익히는 사람이 늘어나거나 다른 프로젝트가 패치를 채택하는 것만으로도 의미가 있다고 본다.

rss · GeekNews · 9월 20일 11:12

**「배경」** Firefox는 Mozilla가 개발하는 오픈소스 브라우저로, ESR\(Extended Support Release\)은 장기 지원 버전을 의미하며 포크 프로젝트들이 기반으로 삼기 용이하다. 하드 포크는 원본 프로젝트와 코드 갈래를 완전히 분리해 독립적으로 유지·관리하는 방식으로, 기존 기능을 껍데기만 끄는 소프트 포크보다 유지보수 부담이 크지만 원치 않는 요소를 근본적으로 배제할 수 있다.

**「영향」** Firefox 기반 프라이버시·경량 브라우저\(Tor Browser, Waterfox 등\) 개발자와 사용자들은 AI 기능이 지속적으로 늘어나는 상위 코드베이스와 결별할 공통 대안을 얻게 될 수 있지만, base browser의 존속 여부는 자원봉사자들의 협력과 자금 확보에 달려 있어 불확실성이 크다.
