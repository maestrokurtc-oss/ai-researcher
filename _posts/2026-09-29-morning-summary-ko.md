### [AMD, Fei-Fei Li의 World Labs를 82억 달러에 인수](https://techcrunch.com/2026/09/28/amd-will-acquire-fei-fei-lis-world-labs-for-8-2-billion/) ⭐️ 9.0/10

AMD가 공간 지능 AI 연구 기업 World Labs를 약 82억 달러 규모의 전량 주식 거래로 인수하는 본계약을 체결했다. World Labs 공동창업자 Fei-Fei Li는 AMD 수석부사장 겸 최고과학자로 합류해 CEO Lisa Su와 직접 협력하며, 공동창업자 Justin Johnson과 Ben Mildenhall도 함께 팀을 이끌며 AMD 내부에 프런티어 AI 연구 조직을 구성할 계획이다. 2024년 설립된 World Labs는 언어만으로 다루기 어려운 3D 공간 이해·생성과 로봇 시뮬레이션을 연구해왔으며, 최근에는 2D 이미지에서 새로운 시점의 장면을 예측하는 Atlas를 공개했고 SceniX 인수로 로봇 시뮬레이션 역량도 확대했다. 양사는 지난해부터 AMD GPU 상에서 모델 학습·추론을 최적화해온 기술 협력을 이어왔으며, 이번 인수를 통해 하드웨어부터 소프트웨어, 플랫폼, 개방형 모델까지 아우르는 엔드투엔드 AI 생태계 구축을 목표로 한다. 거래는 규제 승인 등 통상적인 종결 조건 충족을 전제로 2026년 말까지 마무리될 예정이다.

**「배경」** Fei-Fei Li는 ImageNet 프로젝트로 널리 알려진 AI 연구자로, 2024년 Stanford에서 부분 휴직 상태로 Justin Johnson, Ben Mildenhall과 함께 '공간 지능\(spatial intelligence\)'을 표방하는 World Labs를 공동 창업했다. **「커뮤니티 반응」** 일부 댓글은 Atlas 등 World Labs 데모가 기존 최신 비디오·스플랫 생성 모델과 크게 차별화되지 않고 실사용에는 여전히 부족하다며 기술적 독창성에 의문을 제기했고, 설립 2년 만에 8억 달러도 아닌 82억 달러 밸류에이션이 타당한지 회의적인 시각도 있었다. 반면 다른 댓글은 AMD가 최근 다른 인수와 마찬가지로 이례적으로 빠르게 움직인 점에 주목하며, 초고속 추론과 embodied AI 추론을 겨냥한 포석일 수 있다는 해석을 내놓았다.

### [Anthropic, Claude Sonnet 5.5 출시](https://www.anthropic.com/claude-sonnet-5-5) ⭐️ 7.0/10

Anthropic이 새 모델 Claude Sonnet 5.5를 발표했다. 커뮤니티 테스트에 따르면 PacMan 클론을 한 번에 만들어내는 등 구체적인 코딩 작업에서 이전 Sonnet 버전 대비 향상된 성능을 보이며, 같은 벤치마크에서 최상위 모델인 Opus 5.5에 근소하게 못 미치는 수준의 결과를 냈다. Terminal-Bench 점수에서는 Sonnet 5.5가 70.6점으로 Opus 5.5의 66.4점보다 높게 나왔는데, 이는 Opus가 안전장치로 인해 시도의 10%를 폴백 모델이 대신 처리한 반면 Sonnet은 폴백 비율이 1.5%에 그친 차이에서 기인한 것으로 시스템 카드에 설명되어 있다. Hacker News에서는 698점, 댓글 459개로 활발한 반응을 얻었으며 가격 경쟁력과 중국산 모델과의 비교가 주요 화두로 떠올랐다.

hackernews · D2OQZG8l5BI1S06 · 9월 28일 17:58 · [커뮤니티 반응](https://news.ycombinator.com/item?id=49881850)

**「배경」** Claude Sonnet은 Anthropic의 중급 티어 모델로 일상적인 작업에 최적화되어 있으며, 최상위 모델인 Opus보다 저렴한 가격에 실용적인 성능을 제공하는 것이 특징이다. 이번 Sonnet 5.5는 Sonnet 5 대비 속도가 30% 이상 빨라지고 도구 호출 횟수가 줄어들어 작업당 비용이 약 30% 절감되었으며, 가격 자체는 입력 토큰 100만 개당 2달러, 출력 토큰 100만 개당 10달러로 기존 Sonnet 5와 동일하게 유지되었다. Claude 5.5 패밀리의 두 번째 모델로, 앞서 출시된 Opus 5.5와 함께 Anthropic의 최신 모델 라인업을 구성한다.

**「개발자 및 가격 경쟁에 미치는 영향」** Sonnet 5.5는 Sonnet 5와 동일한 $2/$10 가격을 유지하면서도 약 30% 더 빠른 속도를 제공해, 개발자들이 코딩·에이전트 작업에서 Opus급 성능을 더 저렴하게 활용할 수 있게 되었다. 다만 Terminal-Bench에서 Sonnet 5.5가 Opus 5.5보다 높은 점수\(70.6 대 66.4\)를 기록한 것은 안전장치로 인한 폴백 모델 사용 비율 차이\(Opus 10% 대 Sonnet 1.5%\)가 영향을 미친 것으로 보여, 벤치마크만으로 우열을 단정하기는 어렵다. 또한 GLM, DeepSeek 등 중국 모델들이 훨씬 저렴한 가격에 경쟁력 있는 성능을 제공하면서, Anthropic이 고가 모델 라인업을 강조하는 배경에는 이러한 가격 경쟁 압박이 작용하고 있다는 커뮤니티의 지적이 있다.

**「커뮤니티 반응」** 일부 사용자는 Opus 5.5의 효율이 충분히 좋아 5x 플랜 한도 내에서 일상 작업이 해결되어 Sonnet 5.5를 언제 써야 할지 의문을 제기했다. 다른 댓글들은 Astra, Sol, Fable, Opus 같은 최상위 모델이 아니라면 GLM, DeepSeek 등 중국산 모델이 훨씬 저렴한 비용으로 경쟁력 있는 대안이 될 수 있다고 지적했으며, PacMan 클론 벤치마크에서 Sonnet 5.5가 Opus 5.5에 이어 2위를 차지했다는 실측 결과도 공유되었다. 또한 Terminal-Bench 점수 역전 현상은 실제 모델 성능 차이가 아니라 안전 폴백 비율 차이 때문일 수 있다는 분석이 제기되며 벤치마크 해석에 신중해야 한다는 의견이 나왔다.

### [DuckDB 2.0 알파, 비동기 I/O·재귀 CTE·VARIANT 슈레딩으로 대폭 가속](https://news.hada.io/topic?id=34456) ⭐️ 7.0/10

DuckDB 2.0 알파는 S3 데이터 읽기, 깊은 계층 탐색, JSON 형태 데이터 조회 세 영역을 각각 비동기 I/O, 재귀 CTE 엔진 재작성, VARIANT 필드 슈레딩으로 개선했다. S3 읽기는 다운로드와 CPU 연산을 병렬화해 2.2GB Parquet 파일 한 열 읽기가 18.8초에서 7.7초로, 13.6GB 규모 23개 파일 읽기는 11.8초에서 3.9초로 단축됐다. 재귀 CTE는 매 단계 전체 테이블을 재스캔하는 대신 조회 구조를 한 번 구축해 재사용하는 방식으로 바뀌어, 2만 개 Git 커밋의 조상 탐색이 1.5.5의 1.8~16초에서 0.10초로 줄었다. VARIANT는 여러 행에 일관되게 나타나는 필드를 내부 열로 분리 저장해, 500만 이벤트 실험에서 JSON 문자열 대비 저장 공간이 약 37%로 줄고 필터·집계 속도는 약 6배 빨라졌으며, 슈레딩이 없던 1.5.5 VARIANT 대비로는 약 78배 개선됐다. 이 버전은 2026년 가을 정식 출시 예정이며, 작은 파일 과분산 방지, 일관된 필드 타입 유지, 자주 조회하는 필드의 명시적 열 승격 등 데이터 구조 최적화와 함께 사용할 때 성능 효과가 극대화된다.

rss · GeekNews · 9월 28일 22:24

**「배경」** DuckDB는 별도 서버 없이 단일 프로세스에서 동작하는 임베디드 분석용 SQL 엔진으로, Parquet·CSV·JSON 등 다양한 파일 포맷과 S3 같은 원격 스토리지를 직접 쿼리하는 데 널리 쓰인다. 재귀 CTE\(공통 테이블 표현식\)는 조직도나 Git 커밋 이력처럼 부모/자식 관계로 이어진 계층 데이터를 반복 탐색하는 SQL 기법이며, VARIANT는 스키마가 유동적인 JSON 형태 데이터를 하나의 열 타입으로 담아 저장하는 방식이다.

**「영향」** S3 기반 데이터 레이크 쿼리, 조직도·Git 이력·자재 명세서 같은 깊은 계층 데이터 처리, 반정형 JSON 로그 분석을 DuckDB로 수행하는 데이터 엔지니어와 분석가는 별도의 그래프 DB나 전용 JSON 처리 계층 없이도 상당한 성능 향상을 기대할 수 있다. 다만 알파 단계 수치는 M5 노트북과 가정용 인터넷, us-east-1 리전이라는 특정 환경에서 측정된 것이므로, 실제 도입 전 자신의 환경에서 재측정이 필요하며 VARIANT 리스트 변환처럼 아직 개선되지 않은 약점도 남아 있다.

### [GLM-5.3 희소 주의가 HBM 메모리 사용에 미치는 영향](https://newsletter.semianalysis.com/p/sparse-savings-persistent-demand-inside-glm53) ⭐️ 7.0/10

rss · Semianalysis · 9월 28일 19:26

**「배경」** sparse attention은 top-k로 선별한 토큰만 대상으로 SDPA\(스케일드 닷프로덕트 어텐션\) 연산을 수행해 계산량과 대역폭 요구를 줄이지만, top-k 선택 자체는 전체 컨텍스트가 HBM에 올라가 있어야 하므로 메모리 용량 병목은 그대로 남는다고 저자는 지적한다. 이 때문에 sparse attention의 메모리 프로파일만 보고는 실제 서빙 효율을 판단하기 어렵고, 이를 해결하려는 SGLang의 HiSparse와 Z.ai의 GLM-5.3 설계가 이 글의 분석 대상이다.

**「방안」** 저자는 SGLang팀의 HiSparse가 KV 캐시를 LRU 방식으로 HBM과 호스트 DRAM 사이에서 동적으로 옮기고, 레이어 N-1 실행과 N 레이어 KV 로딩을 겹쳐\(layer-wise overlapping\) 캐시 미스 지연을 줄여 고동시성·긴 컨텍스트에서 처리량을 높인다고 설명한다. GLM-5.3은 DeepSeek Sparse Attention\(경량 인덱서 + sparse MLA\)을 채택하며, vLLM 구현 기준 시퀀스 길이 2K~77K\(텐서 병렬\) 구간에서는 MQA 모드보다 MHA 모드가 더 효율적이라는 임계값을 제시한다. IndexShare는 4개 DSA 레이어가 인덱서 하나를 공유해 인덱서 캐시와 FLOPs를 75% 줄이고 처리량을 1.5~1.8배 높인다. 저자는 GLM-5의 쿼리 헤드 수\(H=64\)가 DeepSeek V3.2의 H=128과 달리 산술 강도 계산상 Moore Threads MTT S4000\(약 128 FLOP/B\)에 맞춰 설계됐을 가능성을 제기하며, Z.ai와 Moore Threads의 협력 정황을 근거로 든다. 서빙 비용 비교에서는 InferenceX 벤치마크 기준 150 토큰/초 처리 시 GB200이 총 토큰당 $0.044로 MI355X ATOM\($0.049\)보다 약 12% 저렴하지만, GB200의 p90 TTFT\(첫 토큰 응답 시간\)가 14~19초로 ATOM의 1.1~1.2초보다 훨씬 길어 실제 지연 제약을 반영하면 우위가 뒤바뀔 수 있다는 트레이드오프도 함께 제시된다. 후반부에서는 post-training 파이프라인의 SAO\(단일 롤아웃 비동기 최적화\)와 slime 프레임워크가 GRPO의 긴 궤적 분산 문제를 GAE 기반 가치 모델로 완화하는 방식도 다룬다.

**「시사점」** 저자의 핵심 주장은 sparse attention이 어텐션 연산 자체의 비용은 줄이지만 메모리 용량 문제를 해결하지 못하며, HiSparse의 계층적 캐시 관리, IndexShare, 하드웨어별 산술 강도 튜닝 같은 시스템 수준 설계가 뒷받침되어야만 GLM-5.3 같은 모델이 실제 서빙에서 비용 절감을 실현할 수 있다는 것이다.
